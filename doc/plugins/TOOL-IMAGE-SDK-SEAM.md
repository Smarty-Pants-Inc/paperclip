1. Existing seam/adopt: [upstream #16517](https://github.com/paperclipai/paperclip/pull/16517) owns the governed MCP projection; this change reuses it, with no second route or wire protocol.
2. Additive core SDK seam: optional top-level `ToolResult.mcpContent` holds bounded text/image blocks; legacy `content` stays a string and arbitrary `data` (including MCP-looking `data.content`) stays opaque and byte-identical without that opt-in.
3. Why: inferring native intent from formerly arbitrary `data.content` broke valid scalar, empty, array and text-only results; an explicit SDK field avoids that ambiguity and invalid opt-ins fail loudly rather than falling back to text.
4. Ownership/safety: registry validates, the existing company storage prepares references, and the gateway governs before the same #16517 projection; logs/run events retain references, native Pi history may retain bodies, and REST without the gateway must reject native opt-in.
