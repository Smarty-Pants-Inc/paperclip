### Important identity/source limit, common to both

Both candidates trust the selected run's **stored `responsibleUserId`** as the source person. Neither proves an immutable historical original-message person against every later identity change or certifies all message/document/attachment bytes unchanged. MINE explicitly allows same-person input edits; THEIRS does not add an input inventory either. The saved **board-message-origin** verifier is a separate, conditional inherited path, not a general unchanged-input gate. The table's identity HOLDS finding is under that supplied interim contract; a stricter immutable-message-lineage requirement is **unproven in both**.

The existing authentication middleware is common: [`server/src/middleware/auth.ts:439–478,502–525`](source-theirs/server/src/middleware/auth.ts.txt) verifies signed run/header consistency and resolves the bound identity; plain-key/header provenance is not equivalent. No real credential was used in this task.
