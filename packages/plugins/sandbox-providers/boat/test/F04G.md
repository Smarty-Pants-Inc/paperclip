# F-04G: bounded live observations and truthful pending-turn admission

## Owners and invariants

The server's remote-process monitor owns its cumulative ten-minute transition
allowance. The Boat plugin owns HTTP recovery and cancellation. The durable
transport owns confirmed-exit restart and the exact pending command's result.
No process exit is inferred from elapsed time; the existing restart guard still
requires confirmed exit. No turn is resubmitted by this change.

An archive configured for 660 seconds cannot be observed archived inside the
600-second allowance. The launcher only has the command runner at this point;
it has neither an archived-state receipt nor authority to resume a lease directly.
Extending the allowance or launching anyway would defeat the bound/guard. This
change therefore uses the brief's permitted fallback:
`runner_process_observation_budget_exhausted`, with an instruction to wait for
archiving and verify the retained runner before explicitly recovering this run.
The server preserves this closed code, terminal disposition and instruction in
both the finalization failure and the source-scoped recovery action. It schedules
no automatic retry. This is NOT a claim that the old process stopped.

The probe sends the remaining per-call allowance as `commandTimeoutMs`, through
the existing runner/runtime/RPC contract. Boat passes that allowance to its
existing HTTP abort path, rather than granting its rounded timeout plus five
seconds of HTTP transport grace. Ordinary execute calls without an explicit
command deadline keep their existing behavior.

Worker RPC drops string error codes. Boat now prefixes its confirmed transition
error with `boat_sandbox_state_transition: `, so live monitoring accepts precisely
that closed code (or its typed WORKER_ERROR form), not arbitrary provider prose.
The broader acquisition-only Daytona retry classifier remains unchanged; it is
no longer used to retain a live process monitor.

For a durably pending `turn.start`, the command waiter tolerates the old PID's
confirmed exit only while the existing watcher is eligible to recover it. It
waits for the SAME command's authenticated result. Explicit rejection, transport
failure, Close and the original deadline still fail; other command types keep
their prior exit behavior. This prevents a false start rejection from entering
the server failure path before the restarted runner delivers its answer.

## Reproduction (repository root)

Prerequisites: workspace dependencies and SDK/shared outputs, isolated Boat
package dependencies/build, real runnerd and fake Codex binaries. Use a private
`TMPDIR`; never point the HTTP fixture at a real Boat service. Every harness
rejects external HTTP destinations. Run long cases under your owned process
reaper and await completion/cleanup.

```sh
node --import ./server/node_modules/tsx/dist/loader.mjs \
  packages/plugins/sandbox-providers/boat/test/real-server-monitor-budget.mjs \
  "$PWD" RUNNERD FAKE_CODEX OUTPUT budget
node --import ./server/node_modules/tsx/dist/loader.mjs \
  packages/plugins/sandbox-providers/boat/test/real-server-monitor-once.mjs \
  "$PWD" RUNNERD FAKE_CODEX OUTPUT all
node --import ./server/node_modules/tsx/dist/loader.mjs \
  packages/plugins/sandbox-providers/boat/test/real-server-monitor-person.mjs \
  "$PWD" RUNNERD FAKE_CODEX OUTPUT absent
```

The budget harness uses a real 660-second archive configuration and an unchanged
600-second product constant, not fake time. It requires the one named fallback,
no fabricated exit, no resume and no replacement. The original a/b/c harness
remains available as `real-server-monitor.mjs`. R-ONCE now requires successful
request admission in addition to one token-bearing provider input, one matching
answer and one delivered answer. The person harness additionally runs the strict
Codex harness session that the native backend uses, requiring one accepted turn,
one completed turn, and zero turn/session failure events. This is local fake-Boat
fault injection with real launch/probe/transport/Rust processes, not deployed
HTTP/database/browser or real daily-work acceptance.
